## เครื่องมือ 3 อย่างที่ dev ใช้ทุกวัน

| เครื่องมือ | ใช้ทำอะไร | เปรียบเหมือน |
| --- | --- | --- |
| Editor | เปิดไฟล์โค้ดทั้งโปรเจค อ่าน เขียน และค้นหา | โปรแกรมพิมพ์เอกสาร แต่ออกแบบมาสำหรับโค้ด |
| Terminal | พิมพ์คำสั่งให้คอมพิวเตอร์ทำ แทนการคลิก | คุยกับคอมพิวเตอร์ผ่านแชต |
| Git | บันทึกงานเป็นช่วง ๆ และย้อนกลับไปช่วงไหนก็ได้ | จุดเซฟในเกม |

ชื่อโปรแกรมและหน้าตาในบทนี้อาจเปลี่ยนไปตามเวอร์ชัน แต่หน้าที่ของเครื่องมือทั้งสามอย่างไม่เปลี่ยน

## Editor: ที่เขียนและอ่านโค้ด

editor ที่นิยมที่สุดตอนนี้คือ Visual Studio Code (VS Code) ใช้ฟรี มีทั้งบน Windows และ Mac สิ่งที่ทำให้มันต่างจากโปรแกรมพิมพ์ทั่วไป คือ

- เปิดทั้งโฟลเดอร์โปรเจคได้ในหน้าต่างเดียว เห็นไฟล์ทั้งหมดทางซ้าย
- ระบายสีโค้ดตามความหมาย อ่านง่ายขึ้นมาก
- ค้นหาคำในทุกไฟล์ของโปรเจคได้พร้อมกัน
- มี terminal อยู่ในตัว ไม่ต้องสลับหน้าต่าง

เครื่องมือ AI หลายตัวทำงานอยู่ใน editor หรือมีหน้าตาคล้าย editor การคุ้นกับ editor สักตัวจึงช่วยให้ใช้เครื่องมือ AI ได้ง่ายขึ้นด้วย

## Terminal: สั่งคอมพิวเตอร์ด้วยตัวอักษร

terminal ดูน่ากลัวในครั้งแรก แต่จริง ๆ มันแค่อีกช่องทางหนึ่งในการสั่งคอมพิวเตอร์ แทนที่จะคลิกเปิดโฟลเดอร์ เราพิมพ์คำสั่งแทน

วิธีเปิด

- **Windows** เปิดโปรแกรม Terminal หรือ PowerShell จากเมนู Start
- **Mac** กด Cmd + Space พิมพ์ Terminal แล้วกด Enter

คำสั่งพื้นฐานที่ใช้ได้ทั้งบน Windows (PowerShell) และ Mac

| คำสั่ง | ทำอะไร |
| --- | --- |
| `pwd` | บอกว่าตอนนี้อยู่ในโฟลเดอร์ไหน |
| `ls` | แสดงว่าในโฟลเดอร์นี้มีอะไรบ้าง |
| `mkdir ชื่อโฟลเดอร์` | สร้างโฟลเดอร์ใหม่ |
| `cd ชื่อโฟลเดอร์` | เข้าไปในโฟลเดอร์นั้น |
| `cd ..` | ถอยออกมาหนึ่งชั้น |

## Git: จุดเซฟที่ย้อนกลับได้

Git คือเครื่องมือที่จดประวัติการเปลี่ยนแปลงของโปรเจค คำที่ต้องรู้มีแค่สามคำ

- **repository** คือโฟลเดอร์โปรเจคที่ Git ดูแลอยู่
- **commit** คือจุดเซฟหนึ่งจุด พร้อมข้อความสั้น ๆ ว่าเปลี่ยนอะไรไป
- **history** คือรายการ commit ทั้งหมดเรียงตามเวลา

ลองนึกภาพโปรเจคเว็บจดสิ่งที่ต้องทำที่มีประวัติแบบนี้

1. commit "สร้างหน้าแรก"
2. commit "เพิ่มปุ่มเพิ่มรายการ"
3. commit "ให้จำรายการไว้หลังปิดหน้า"

ถ้าเปลี่ยนแปลงครั้งที่ 3 ทำให้หน้าเว็บพัง เราย้อนกลับไปที่จุดเซฟที่ 2 ได้ทันที โดยไม่ต้องจำว่าเคยแก้อะไรไปบ้าง

Git สำคัญมากขึ้นอีกเมื่อทำงานกับ agent เพราะ agent แก้ได้หลายไฟล์ในเวลาไม่กี่วินาที ถ้าผลออกมาไม่ดี วิธีที่ง่ายที่สุดคือย้อนกลับไป commit ก่อนหน้า ดังนั้น **ให้ commit งานก่อนทุกครั้งที่จะให้ agent ลงมือแก้** วิธีใช้ Git ทีละขั้นอยู่ใน <ChapterLink number={10} />

<Callout tone="case" title="เคสจริงจาก MilerDev">

ทุกการเปลี่ยนแปลงของเว็บนี้ถูกบันทึกเป็น commit พร้อมเหตุผล เช่น ตอนที่เราตัดหน้าตั้งค่าที่ไม่มีโค้ดส่วนไหนอ่านค่าออกจากหลังบ้าน ถ้าภายหลังพบว่ามีปัญหา เราย้อนการเปลี่ยนแปลงนั้นได้ในคำสั่งเดียว และย้อนดูได้เสมอว่าใครเปลี่ยนอะไร เพราะอะไร

</Callout>

## agent ใช้เครื่องมือชุดเดียวกัน

เมื่อเข้าใจเครื่องมือทั้งสามแล้ว จะเห็นว่า agent ทำงานแบบเดียวกับ dev

- อ่านและแก้ไฟล์ เหมือนที่เราทำใน editor
- รันคำสั่ง เหมือนที่เราพิมพ์ใน terminal
- บันทึกงาน เหมือนที่เราใช้ Git

ดังนั้นเวลา agent ถามว่า "ขออนุญาตรันคำสั่ง `npm install`" เราจะพอเดาได้ว่ามันกำลังจะติดตั้งโปรแกรมเสริม และตัดสินใจได้ว่าจะให้ทำหรือไม่ ดูการทำงานของ agent ต่อใน <ChapterLink number={5} />

## ข้อผิดพลาดที่พบบ่อย

1. **วางคำสั่งจากอินเทอร์เน็ตลง terminal โดยไม่เข้าใจ** คำสั่งบางคำสั่งลบไฟล์หรือส่งข้อมูลออกไปได้
2. **ทำงานผิดโฟลเดอร์** พิมพ์ `pwd` ตรวจก่อนรันคำสั่งที่สร้างหรือลบไฟล์
3. **ให้ agent แก้งานโดยไม่ commit ก่อน** ถ้าพังจะย้อนกลับยาก
4. **กลัว terminal จนไม่กล้าใช้** เริ่มจากคำสั่งที่อ่านอย่างเดียว เช่น `pwd` และ `ls` ซึ่งไม่เปลี่ยนอะไรในเครื่อง
